# BotSopa: frontend en Dokploy

Repositorio: `robotsopa-frontend` (el remoto configurado usa este nombre). Seleccione Docker Compose, archivo `./compose.dokploy.yml`, contexto raíz y una rama que contenga estos archivos. Configure un dominio HTTPS para el servicio `front`, puerto interno 80; no publique un puerto del host. Angular usa `/api/v1/` en el mismo dominio y no necesita variables ni secretos de construcción.

La red externa `botsopa-sri-network` debe existir en el mismo host antes del despliegue (ver guía del backend). La API se busca como `botsopa-sri-api:8080`. Nginx usa el DNS de Docker, vuelve a resolver cada 10 segundos y puede iniciar aunque la API esté ausente; durante interrupciones devuelve 502/503 hasta que vuelva. `/health` comprueba solamente Nginx. No hay dependencia entre Compose. `/api/internal/` no se expone. El Host original se conserva; se sustituyen los encabezados reenviados aportados por el cliente. El esquema reenviado es el del salto a Nginx, no prueba del HTTPS externo; la API fuerza Secure por configuración propia.

En Dokploy v0.30.10 configure TLS y redirección HTTP a HTTPS. En Domains use el servicio `front`, puerto 80, HTTPS y el certificado correspondiente. El Compose conecta explícitamente `front` a `dokploy-network` para Traefik y fija `traefik.docker.network`; mantenga esa conexión y la red `botsopa-sri-network` en la gestión de redes por servicio y compruebe Preview Compose. No use Isolated Deployments, opción heredada y obsoleta desde v0.30. No asigne dominio a la API. En el navegador verifique login, cookie `sri-session` con Secure, HttpOnly y SameSite=Strict, recarga, cierre de sesión, y el acceso a `/api/v1/auth/session`. La sesión en memoria se pierde al reiniciar API.
